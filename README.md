# Predicting Repeat Purchases

Binary classification of whether a wholesale customer makes another purchase
within 90 days of the current one. Group 06 homework for Machine Learning
2026/27 (NOVA IMS), structured with CRISP-DM.

Each observation is a purchase occasion (`ID`); a customer (`customer_id`) can
appear many times. The target is `repeat_purchase_90d` (1 = another purchase
within 90 days). The evaluation metric is binary F1 for the positive class, as
used on Kaggle.

## Results

Final model: **random forest with L1 feature selection and a 0.40 decision
cutoff**.

| Model | Development F1 (3 folds) | Holdout F1 | Precision | Recall | Accuracy |
|---|---:|---:|---:|---:|---:|
| Majority-class baseline | 0.7044 | 0.7525 | 0.6032 | 1.0000 | 0.6032 |
| Random forest + L1, cutoff 0.5 | 0.7388 | 0.7818 | 0.7979 | 0.7663 | 0.7419 |
| **Random forest + L1, cutoff 0.40** | **0.7451** | **0.7915** | **0.7209** | **0.8774** | **0.7211** |

Holdout confusion matrix: TN = 249, FP = 266, FN = 96, TP = 687. The lower
cutoff trades accuracy for recall, which improves F1.

## Approach

**Data.** 6,534 training purchases, 986 test purchases and 1,143 customer
records (`data/raw/`). Ten exact duplicates and 55 undated records without
purchase information are removed, leaving 6,469 training purchases.

**Validation.** The test set lies after the training period, so validation is
chronological:

- Holdout: the latest ~20% of dated purchases (1,298, from 17 June 2023).
- Development: 5,024 purchases up to 18 March 2023.
- A 90-day gap (147 purchases) separates the two, so every development label
  is known before the holdout starts.
- Model selection uses three expanding temporal folds inside development,
  each with its own 90-day gap. The holdout is not used for any choice.

**Cleaning.** Invalid negative values and a repeated `1e9` placeholder are set to
missing. Historical averages inconsistent with total spend / purchase count are
recalculated; impossible historical maxima and annual spend are set to missing.
Large but consistent amounts are kept.

**Feature selection.**

- Identifiers, the empty `customer_type`, company name, address, street and
  postal code are excluded.
- Statistical tests on development data (ANOVA, Mann-Whitney U, mutual
  information, chi-square with Cramér's V) show no relationship for
  `random_noise` and `Total Portes`, which are removed.
- The purchase year is excluded: test purchases fall in 2025-2026, after all
  training data, so year effects cannot transfer.
- L1-regularised logistic regression (`C=0.1`) selects inputs inside each
  training fold: 52 of 273 on the full development set.

**Preprocessing** (fitted on each training fold only): median imputation with
missing-value flags, a `Missing` category for text, `log1p` on monetary
variables, standard scaling, and one-hot encoding with categories below 20
occurrences pooled.

**Models.** Logistic regression (`C=1`), decision tree (`max_depth=5`,
`min_samples_leaf=20`) and random forest (200 trees, `min_samples_leaf=5`), each
with all inputs and with the L1 subset, against a majority-class baseline.
Every model is evaluated at cutoffs from 0.20 to 0.60. The two random forests
tie at 0.40 (0.7457 without selection, 0.7451 with L1, well within the fold
standard deviation of about 0.013); the L1 version is kept as the simpler model.
Hyperparameters were fixed in advance, not tuned.

**Deployment.** The pipeline is refitted on all 6,469 training purchases
(299 inputs, 56 kept by L1) and applied to the test set with the 0.40 cutoff:
767 predicted repeats and 219 non-repeats.

## Reproducing the results

The notebooks were run with Python 3.13.5, pandas 3.0.3, NumPy 2.4.6 and
scikit-learn 1.9.0. scikit-learn 1.8 or later is required, because the L1
selector uses `l1_ratio=1`.

```bash
conda env create -f environment.yml
conda activate machine_learning
```

Run the notebooks in order (01 to 06) from the `notebooks/` directory, each in a
fresh kernel. Notebook 03 starts from the raw data; random seeds are fixed, so
the results and submission are reproducible.

## Limitations

- First purchases are the weakest group: with no purchase history, the model
  finds 5 of the 12 repeat purchases among the 44 first purchases in the holdout.
- The holdout is a single later period, and an earlier group exploration used
  the full training file, so it is not completely untouched.
- Customers appear in many rows, so scores are per purchase, not per customer.
- Cleaning assumes the supplied total spend and purchase counts are reliable.

taught algorithms, hyperparameter optimisation and an additional investigation.
